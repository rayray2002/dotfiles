## Dev tools
- **Python projects: uv.** If a project has `pyproject.toml` / `uv.lock`, use `uv sync`,
  `uv run <cmd>`, `uv add <pkg>`; for a quick venv, `uv venv && uv pip install ...`.
  Don't `pip install` into a system or base Python.
- **Conda environments: micromamba**, aliased `mamba`. Use it when a project needs conda
  packages (CUDA toolkits, compiled libs, non-Python deps) or already has an
  `environment.yml`: `mamba create -n NAME python=3.12`, `mamba activate NAME`,
  `mamba env create -f environment.yml`. Inside an activated env, `uv pip install` is the
  fast pip. Never install into `base`.
- Env roots (`MAMBA_ROOT_PREFIX`): `~/miniforge3` on the Mac and Linux machines,
  `/scr/borueihu/miniforge3` on snoopy. List envs with `mamba env list`.
- Credentials are already set up on every machine: wandb (`~/.netrc`) and Hugging Face
  (token in `$HF_HOME`), so `wandb` and `huggingface_hub` work without logging in.
- CLI tools everywhere: rg, fd, bat, eza, jq, gh, lazygit, delta, difftastic, ast-grep,
  hyperfine, watchexec, direnv (`.envrc`, with nix-direnv), zoxide (`z`), tmux.
  Prefer `rg` / `fd` over grep / find.
- Shell is zsh. Nix provides the tools (`~/.nix-profile/bin` comes first on PATH).

## Dotfiles
- Everything in `~` that is a symlink into `/nix/store` is generated by home-manager from
  the dotfiles repo. Edit the repo, never the generated file, then `dots-sync "msg"`
  (commits, applies here, pushes, updates the other machines). `dots-status` shows every
  machine's state. Docs: `docs/` in the repo.

## snoopy (Slurm GPU server)
- Rootless Nix: interactive logins enter an env where `$HOME` is `/scr/borueihu/nixhome`;
  the real home is `/home/borueihu` (~15 GB quota). Put data, checkpoints, caches and
  environments on `/scr/borueihu/...`, never in a home directory.
  `HF_HOME=/scr/borueihu/cache/huggingface`.
- Never run GPU work on the login shell; `nvidia-smi` there only works inside a job.
  - `gpus`: which GPUs are free and who uses the rest.
  - `sgpu [n] [time]`: interactive shell on GPUs (1 GPU uses `phd`, 2-3 use `partition-1`).
  - `snew NAME`: new sbatch from the usual template; submit with `sbatch NAME.sbatch`.
  - `sq` my jobs, `sqa` all jobs, `slog [job]` follow a log, `sk` cancel, `shist` history.
  - Limits: `phd` QoS = 1 GPU / 16 CPUs per job; `partition-1` = 3 GPUs per user.
  - Other people's jobs share the machine: request only what a job needs, and don't
    submit jobs (or `sgpu`) without being asked to.
- Jobs start outside the Nix env: in sbatch scripts use absolute paths to the env's
  python (e.g. `/scr/borueihu/miniforge3/envs/NAME/bin/python` or a project `.venv`).

## Secrets
